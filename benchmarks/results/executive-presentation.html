SECTION 02

What Changed Architecturally

From an eager, always-on runtime to a context-aware, deferred one — with every public contract preserved.

Before

Every request paid the full cost

Runtime Architecture — Before (Eager, Always-On)
graph TD R["HTTP Request"] --> S["wp-settings.php: 324 eager require/include"] S --> A["All subsystems load eagerly, including the 53 REST controller classes"] A --> F["default-filters.php: 465 hook registrations"] F --> H["WP_Hook dispatch: always call_user_func_array()"] H --> Q["WP_Query: per-object meta/term queries (N+1)"] Q --> C["Object cache: coarse flush, single get/set"] C --> Z["Response"]

The Runtime Architecture — Before (Eager, Always-On) diagram shows how a single request always loaded every subsystem, registered all hooks, and dispatched them through the general-purpose call path — then re-queried metadata object by object.

Boxes = runtime stages Full path runs for every context
After

Defer REST controllers on non-REST requests

Runtime Architecture — After (Context-Aware, Deferred)
graph TD R2["HTTP Request"] --> CTX{"Non-REST front-end? WP_USE_THEMES and not is_admin and not wp_is_rest_request"} CTX -->|yes| S2["Defer 53 REST controller classes to rest_api_init + spl_autoload_register safety net"] CTX -->|no| S3["Load all 53 REST controllers eagerly"] S2 --> F2["default-filters.php: same 465 registrations preserved"] S3 --> F2 F2 --> H2["WP_Hook: arity fast path, direct-call for 0-1 args"] H2 --> Q2["WP_Query: batch prime meta/terms in bulk"] Q2 --> C2["Object cache: multi-get/set, granular invalidation, hit/miss counters"] C2 --> STx["Server-Timing: emit 7 metrics (test env only)"] STx --> Z2["Response: identical output, fewer files/queries"]

The Runtime Architecture — After (Context-Aware, Deferred) diagram defers the 53 REST controller classes to rest_api_init behind an spl_autoload_register() safety net on non-REST front-end requests (other contexts load them eagerly), routes low-arity hooks through a direct fast path, and primes metadata in bulk — while the output stays byte-identical.

Diamond = non-REST front-end predicate (wp_is_rest_request) Non-REST front-end defers 53 REST controllers; other contexts load eagerly Public contracts unchanged

SECTION 03

Risks & Safeguards

How we protected the sites running on WordPress from regressions while changing the runtime hot path.

Risks & Mitigations

Changed the engine, kept the contract

RiskSafeguardStatus
Public API preservation Method signatures, hook names and argument counts, REST routes/schemas and the wp.* surface are unchanged; 465 registrations, 546 do_action and 1,485 apply_filters sites remain intact. Mitigated
Security-order preservation Authentication, nonce and capability gates stay in the non-deferred core bootstrap; deferred files contain only class definitions and registrations. Mitigated
Admin JS ≥30% target Admin JS transfer is essentially flat (-0.00%): the admin bundles load eagerly by design and webpack cannot split the Grunt-uglified admin JS, so reaching the target requires relocating admin JS onto webpack entry points with splitChunks — the prioritized next step, deferred under the minimal-diff principle. Deferred
Minimal-diff discipline The in-request query cache is read-only (SELECT only), keyed by exact SQL with a bounded 256-entry FIFO; no bundled refactors or style-only edits. Mitigated
PHPUnit: baseline parity QUnit 456: baseline parity PHPStan: zero new errors PHPCS: zero new violations

The full PHPUnit suite matches baseline on the documented PHP 8.3 CI toolchain. On the PHP 8.4.11 measurement host, eight deprecated-timezone tests fail identically to a clean baseline checkout — an environmental timezone-database delta, not a regression.
