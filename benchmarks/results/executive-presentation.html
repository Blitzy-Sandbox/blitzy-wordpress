SECTION 02

What Changed Architecturally

From an eager, always-on runtime to a context-aware, deferred one — with every public contract preserved.

Before

Every request paid the full cost

Runtime Architecture — Before (Eager, Always-On)
graph TD R["HTTP Request"] --> S["wp-settings.php: 324 eager require/include"] S --> A["All subsystems load: block editor, REST, new-7.0, admin (any context)"] A --> F["default-filters.php: 465 hook registrations"] F --> H["WP_Hook dispatch: always call_user_func_array()"] H --> Q["WP_Query: per-object meta/term queries (N+1)"] Q --> C["Object cache: coarse flush, single get/set"] C --> Z["Response"]

The Runtime Architecture — Before (Eager, Always-On) diagram shows how a single request always loaded every subsystem, registered all hooks, and dispatched them through the general-purpose call path — then re-queried metadata object by object.

Boxes = runtime stages Full path runs for every context
After

Load only what the context needs

Runtime Architecture — After (Context-Aware, Deferred)
graph TD R2["HTTP Request"] --> CTX{"Detect context: front-end / admin / REST / AJAX"} CTX --> S2["wp-settings.php: load only files needed for context"] S2 --> F2["default-filters.php: same 465 registrations preserved"] F2 --> H2["WP_Hook: arity fast path, direct-call for 0-1 args"] H2 --> Q2["WP_Query: batch prime meta/terms in bulk"] Q2 --> C2["Object cache: multi-get/set, granular invalidation, hit/miss counters"] C2 --> STx["Server-Timing: emit 7 metrics (test env only)"] STx --> Z2["Response: identical output, fewer files/queries"]

The Runtime Architecture — After (Context-Aware, Deferred) diagram adds a context branch so only relevant subsystems load, routes low-arity hooks through a direct fast path, and primes metadata in bulk — while the output stays byte-identical.

Diamond = context branch Only relevant subsystems load Public contracts unchanged

SECTION 03

Risks & Safeguards

How we protected the sites running on WordPress from regressions while changing the runtime hot path.

Risks & Mitigations

Changed the engine, kept the contract

RiskSafeguardStatus
Public API preservation Method signatures, hook names and argument counts, REST routes/schemas and the wp.* surface are unchanged; 465 registrations, 546 do_action and 1,485 apply_filters sites remain intact. Mitigated
Security-order preservation Authentication, nonce and capability gates stay in the non-deferred core bootstrap; deferred files contain only class definitions and registrations. Mitigated
Admin JS ≥30% target Conditional loading lands now at 17.97%; true webpack bundle splitting is the wired, prioritized next step to reach the target. Partial
Minimal-diff discipline The in-request query cache is read-only (SELECT only), keyed by exact SQL with a bounded 256-entry FIFO; no bundled refactors or style-only edits. Mitigated
PHPUnit 28,930 (28,923 pass) QUnit 456 / 456 PHPStan: zero new errors PHPCS: zero violations
